    A11y Demo

    One copy of a demo on the Accessibility page. The page loops over the view's demo_copies inside an .a11y-compare wrapper, passing each as :copy: the simulated copy, which the page's vision simulations filter, then a typical-vision copy for the "Compare with typical vision" toggle. The typical copy is aria-hidden and inert, and stays hidden until the toggle is checked. Suffix any id inside the slot with copy.suffix. class styles the demo's own box, such as its grid. Without copy, as here, it renders the simulated copy alone.

    Site brand, linking home. With court_name set it shows the court's logo and name with a "Powered by Free Law Project" line under both; without it, the Free Law Project lockup. court_name_image is optional art for the name, with court_name as its alt text.     Form Errors

    Renders non-field errors from a Django form as a danger alert. Outputs nothing when there are no errors. Pass the form object via the :form prop.

    Example: Your password must contain at least 8 characters.

    Usage

    <c-molecules.form-errors :form="form" />

    Props

    :form Django form instance (reads form.non_field_errors)

    Toast Container

    Renders Django flash messages as auto-dismissing toast overlays. Included in base.html.

    Composes c-atoms.auto-dismiss (at a 5s timeout, so sentence-length messages stay readable) and c-atoms.alert. No props — reads messages from template context.

    User Menu

    Header user menu — shows sign-in link for anonymous users, dropdown with profile/logout for authenticated users. Used inside c-organisms.header.

    No props — reads user from template context. Requires the userMenu Alpine.js component.

    Empty State

    What fills a site frame region before the visitor has anything to put there: an icon, one sentence on what will collect there, and an optional action. Props: icon, text, action_label, action_href.

    Site Menu

    The header's menu: About, Privacy and Accessibility in every environment, account links on phones (where the user menu is hidden), and a dev-tools group outside production. A native <details> over a plain link list, so it works without JS. One prop, confirm_id, gives the Start over confirmation its own id when two menus share a page, as here.

    Selector Card

    One option in a row of illustrated choices, such as the Atomic Design levels. A plain link, so choosing works without JS. Pass :current to mark the chosen card with aria-current="page", a tint and a check icon. The thumb slot holds a decorative picture; label names the option. Place each card in an <li> of a list-none pl-0 list.

    orientation="vertical" (default): picture above label, for a grid of cards. Below md the picture shrinks beside the label.

    Site Frame

    The layout chat, home and the topic flow share (#988): a left region, <main>, and a right region, in that reading order. From xl up the regions sit beside the content, sticky under the header. Below xl each is a native popover drawer, opened by the header's buttons with no JS; the frameDrawer Alpine component moves focus in on open, and closes the drawer when focus leaves or a link inside it is followed.

    Pages don't use it directly: they extend frame_base.html and fill frame_left, content and frame_right. It isn't rendered live here because it holds the page's one <main>; chat, home and the topic flow show it in place.

    Props: left_label, left_icon, right_label, right_icon. Slots: left, right, and the default slot for the content.

    Briefcase Panel

    The site frame's right region on every framed page: the visitor's stored facts, grouped by interview page. Pass the grouped list via the :groups prop, as built by variable_answer_groups(). Groups with no title render their facts without a heading, which is where unplaced answers land. The same region is the desktop column and the mobile drawer, so the two cannot drift.

    Always renders. With no facts it shows its empty state rather than collapsing, because the panel is a fixed part of the chat frame. A raw agent-state disclosure appears at the bottom for users holding manage_developers.
